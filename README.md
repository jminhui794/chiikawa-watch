# 치이카와 극장판 상영 감시기

`극장판 치이카와: 인어 섬의 비밀` (2026-09-30 개봉)의 **9/19~9/20 사전 상영회**를
감시해서 새 회차가 열리거나 취소표가 나오면 **Windows 토스트 알림**을 띄운다.

## 동작

GitHub Actions가 4개 체인을 조회하고 `.watch-state.json`의 공통 기준과 비교한다.
예약은 5분 간격이지만 GitHub 실행 대기로 지연될 수 있다.
기본 휴대폰에 발송한 새 회차·취소표 알림을 같은 파일의 `events`에 기록하고,
PC는 30초마다 이 기록을 읽어 같은 제목과 내용을 표시한다. PC는 영화관을 별도로 조회하지 않는다.
따라서 PC를 꺼도 휴대폰 감시는 계속되며, PC 재시작 시 최근 7일/최대 500건 중 미확인 알림을 표시한다.
최초 설치 시에는 과거 알림을 생략한다. `.desktop-alerts.json`에 PC 수신 기록을 저장한다.
기존 회차 기록은 자동으로 새 형식으로 전환하며, 전환 자체로 새 회차 알림을 보내지 않는다.

영화관 4곳은 서로 독립적으로 조회하며, 같은 영화관의 API 요청은 최대 4개만 동시에 보낸다.
각 API 요청은 최대 8초, 일시적 오류는 1회 재시도, 영화관별 API 묶음은 최대 120초로 제한한다.
성공한 영화관부터 바로 결과를 저장하고 알림을 보내므로 느린 영화관 때문에 전체가 대기하지 않는다.
실패한 지점·날짜는 이전 기록을 보존한다. `.watch-state.json`의 `health`에 소요 시간과 실패 범위를 기록한다.
일부 조회 실패 시에도 성공한 결과는 발송하고, Actions 실행은 실패 상태로 표시해 불완전한 조회를 숨기지 않는다.
알림은 `outbox`에 먼저 저장하고 발송 성공 후 제거한다. 전송 실패는 다음 실행에서 재시도하며,
회차가 6건을 넘으면 나눠 발송한다. 전송 성공 직후 기록 저장이 실패하면 재시도 시 중복 수신할 수 있다.
테스트 알림은 별도 실행 그룹에서 영화관 조회·브라우저 설치 없이 발송하며, 기록 충돌은 최신 상태에 재적용한다.
정기 조회 사이에 생겼다가 팔린 좌석, 영화관 접근 차단, 휴대폰 OS의 알림 전달 지연까지 방지할 수는 없다.

| 체인 | 방식 | 감지 범위 |
|---|---|---|
| 롯데시네마 | `GetPlaySequence` API | 영화·날짜·지점 확인, `IsBookingYN=Y` 및 **BookingSeatCount 자체가 잔여석** |
| 메가박스 | `selectBokdList.do` API | 영화 코드·날짜·`formAt=Y` 확인. 날짜별 편성 여부만 |
| 씨네큐 | `/popup/ReserveScreenPlan` | 지점·날짜별 실제 시간표, 상영관·시작 시간·잔여석/매진 확인 |
| CGV | `searchSchByMov` API | 영화·지점·날짜 확인, 예매 상태 및 `frSeatCnt` 잔여석 |

알림 종류
- 🎬 **새 회차 오픈** — 직전에 없던 회차가 생김
- 🎟️ **취소표 발생** — 잔여 0석이던 회차에 자리가 남 (CGV·롯데·씨네큐)

## 실행

이미 **시작프로그램에 등록**되어 있어 로그인하면 자동으로 뜬다.
(`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\ChiikawaWatch.vbs`)

```powershell
# 수동 1회 실행 (콘솔에서 결과 확인)
python watch.py --once

# 수동 상시 실행
python watch.py

# 중지
Get-Process pythonw | Stop-Process
```

## 설정 — `config.json`

- `watch_dates` — 감시할 날짜 (`YYYYMMDD`). 개봉 후에도 쓰려면 `"20260930"` 등을 추가
- `poll_seconds` — 폴링 주기 (기본 300초)
- 각 체인의 극장 코드는 서울 전역 + 남양주로 채워져 있음

## 알려진 한계

### CGV 미지원 — 실제 조회 성공 확인 필요

2026-09-15 이 PC의 숨김 Chrome으로 CGV 예매 페이지에 접속했을 때,
CGV가 접근 제한 화면을 반환했다. 회차·좌석 응답을 검증하지 못했으며
**CGV 알림 연동은 아직 미완료**다. 기존 문서의 "로그인이 반드시 필요하다"는
결론도 확인되지 않았다.

현재 코드는 CGV 페이지에서 조회를 시도하고 접근 제한, HTTP 오류,
예상과 다른 응답 형식을 오류로 기록한다. 조회 실패 시 이전 CGV 기록을 유지하여
실패 후 복구를 새 회차 오픈으로 오인하지 않도록 했다. 일부 지점만 조회된
경우에도 CGV 전체 기준선을 갱신하지 않는다. 유지된 기록은 최신 조회 결과가 아니다.

일반 Chrome에서 CGV 극장별 상영시간표가 열리는지 확인한 뒤,
정상 화면이 사용하는 회차·잔여좌석 응답을 확인해야 연동을 완료할 수 있다.
로그인만으로 해결된다고 보장할 수 없다.

로그인 상태를 사용하는 조회를 위해 전용 Chrome 프로필을 지원한다.

```powershell
python cgv_session.py
```

열린 창에서 직접 로그인하고 극장별 상영시간표를 확인한 뒤 창을 닫는다.
다음 감시 실행부터 `.cgv-profile`의 로그인 상태를 사용한다.
이 폴더에는 로그인 정보가 저장되므로 공유하지 않는다. 로그인 만료 시 위 명령을
다시 실행한다. 프로필을 동시에 열 수 없으므로 로그인 작업 중에는 감시기를 중지한다.
로그인 프로필 지원은 회차 API 연동 완료를 의미하지 않는다.

실패 처리 검증 (네트워크·알림·상태 파일 변경 없음):

```powershell
python -m unittest -v test_watch
```

### 기타

메가박스는 회차별 잔여좌석을 제공하지 않아 취소표 감지가 불가능하다.
**취소표까지 잡히는 건 롯데시네마뿐이다.**

## 폰 알림의 기기별 범위

`PUSH_SUBSCRIPTION`의 첫 번째 항목(단일 객체라면 해당 기기)은 처음 등록한 기본 기기로 취급하며,
기존 등록 코드의 날짜·영화관 제한과 관계없이 `config.json`의 모든 감시 대상에 대한 새 회차·취소표 알림을 받습니다.
추가 기기는 각자의 `dates`, `theaters` 조건을 따릅니다. 기기 목록을 수정할 때 기본 기기를 첫 번째에 유지해야 합니다.
기본 기기의 범위를 복구하기 위해 폰에서 등록 코드를 다시 만들 필요는 없습니다.
이미 처리한 과거 변화는 재전송하지 않으며, 수정된 서버 코드가 배포된 뒤 감지하는 변화부터 적용됩니다.
